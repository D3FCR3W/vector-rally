## Remaining Studio work

The Studio source repository is on another computer. These items require work there; the project is deliberately not marked complete.

1. **Native rendering support.** Experience cannot execute the Canvas/WebGL renderer, exact landing-grid transforms, live wildlife/physics, tunnel cutaways, replay clock or video encoder. Static captures and form transitions remain approximations. Follow the existing [renderer defect report](studio-experience-rendering-report.md) for overlay containment, layout and image handling.
2. **Replay input parity.** The native timeline is a range input clamped to the recording duration. Experience provides a numeric field. `simulate_experience` accepts `-1` through both typing and a change interaction even with `inputType: number` and a minimum validation; its validation function runs through submit/click gates. Avoid adding a submit gate to Back to race, which would change the native behavior. Implement a real range control or clamping on numeric change and test lower/upper bounds and non-numeric input.
3. **Generated parameter refresh.** Updating the type/binding of an existing builder input can leave its generated action parameter at the old type/path. Recreating the input identity fixes the current project, but Studio should regenerate or reconcile the existing parameter. Regression case: change Replay timeline from a string to numeric binding, then run the global type-compatibility check. Final node: `bld-vr-replay-time-number`; speed: `bld-vr-replay-speed-v2`; paths: `bld-vr-replay-paths-v2`.
4. **False drift after evidence sync.** `sync_implementation_index` successfully recorded all evidence, but its status reports advanced feature `updatedAt` (for example setup to `2026-09-11T01:23:59.470Z`). A subsequent drift check called the freshly seeded index stale. Refreshing seed versions after synchronization, without changing behavior or resubmitting the same metadata, yields zero drift. Studio should distinguish semantic spec revisions from implementation-report revisions. Test `seed → sync → drift` with no specification edits.
5. **Shared index keys.** Studio reports 31 shared keys and consumes one primary code location per key. The local index retains every reviewed feature-specific location and spec version. Studio should preserve these contexts rather than treating the last location as the only evidence for every feature.

The two native renderer/export issues remain open in Studio. The Experience section remains unapproved; successful local prototype verification does not override that fidelity limit.
